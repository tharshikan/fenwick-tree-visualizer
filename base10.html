Base-10 Fenwick Lab

In base 10 a digit can be 0–9, so you may need up to 9 pieces per digit. That cost has to land somewhere. Version A uses fixed coin sizes (1, 10, 100) and puts the cost on queries. Version B lets one chunk cover the whole last digit group and puts the cost on updates. Switch between them on the same array to see the trade-off.

    The trade-off
    
  
    
    
    
      
    Worst case on this array (exact, n = )
    
      
    
    
    
    
    
      
    Why base 2 wins: (b − 1) · logb n
    
      
    
        
      
    
      
    
      
    Exact worst cases, computed over every position 1..n. A larger base means fewer digits, but each digit can need up to b − 1 pieces, and that factor grows faster than the digit count shrinks. Base 2 is the only base where b − 1 = 1, so both columns match.
    
    
    
    
    
      
    
        
    The hardware reason
    
        
    Even with equal step counts, binary would still be faster. Finding the lowest set bit is i & -i, one or two instructions. Finding the lowest nonzero decimal digit takes the while (i % 10 == 0) loop in the code panel, and integer division is among the slowest things a CPU does.
    
      
    
      
    
        
    Where a wide base wins
    
        
    A B-tree is like base 200. On disk, loading a node is the expensive part and scanning 200 keys inside it is nearly free, so fewer levels win. A BIT counts every memory read about equally, so base 2 wins there.
